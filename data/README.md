# Data card — synthetic care-home cohort

## Summary

A fully synthetic, single-home cohort of **50 residents observed for 365 days**
(21 Aug 2025 – 20 Aug 2026), generated by `synthetic_cohort.py` from seed 4242.
It is not a random filler: it is an explicit data-generating process (a
hierarchical latent state-space model with a discrete-time hazard for falls), so
every downstream result can be traced back to known ground truth.

**No real person, staff member or care home is represented.** Phone numbers use
the Ofcom drama range (07700 900xxx), emails use `example.com`, and GP names are
invented.

## Contents

| Table | Rows | What it is |
|---|---:|---|
| residents | 50 | Demographics, diagnoses, allergies, capacity, mobility, diet, next of kin |
| care_notes | 15,393 | Daily notes: personal care, nutrition, fluids, mood, sleep, narrative |
| mar_records | 93,440 | Medication administration record entries |
| handovers | 6,100 | Shift handover entries |
| wellbeing | 1,350 | Structured wellbeing scores |
| family_comms | 600 | Family communications |
| risk_assessments | 350 | Falls, pressure, nutrition and other risk scores |
| incidents | 268 | Incidents, including 135 falls |
| medications | 256 | Active prescriptions |
| care_plans | 50 | Structured care plans |

The full database is a build output and is not committed (19 MB). Rebuild it with
`python setup_project.py --skip-train` (about a minute, deterministic).

`data/sample/` holds a browsable CSV slice: every table for residents
RES001–RES005, written by `python export_sample_data.py`. The `users` table
(password hashes) is never exported.

## Fidelity checks

Generated by `setup_project.py` into `results/synthetic_data_validation.json`.

| Check | Value | Reference |
|---|---|---|
| Falls per resident-year | 2.7 | 2.2–3.8 in the FinCH trial (Logan et al., NIHR HTA 26(9), 2022; 84 UK care homes) |
| Falls over-dispersion (variance / mean) | 4.12 | Falls cluster in a minority of residents, as in practice |
| Mean age | 85.7 (SD 4.9) | Typical UK care-home population |
| Documentation rate | 0.84 notes per resident-day | — |
| Notes thin as residents deteriorate | r = −0.60 (falls vs notes) | Designed missing-not-at-random documentation |
| Missed-dose rate (MAR) | 10.7% | — |

## Ground truth

The latent health state and true daily fall hazard are written to
`carehome_ground_truth.json.gz` (git-ignored). The model never reads it;
`oracle_benchmark.py` uses it to compute the best achievable performance, which
bounds what any model trained on the observable records could reach.

## Known limitations

- One synthetic home, 50 residents: results say nothing about real-world
  performance.
- Free-text notes come from templates with controlled variation, so they are
  more regular than real care notes.
- Gender is assigned from the first name; age, frailty and medication count are
  available but no subgroup analysis has been run yet.

## Changelog

- Next-of-kin relationships now match the relative's name (no more "Pauline
  Brown (Son)"). As with gender, the random draw is kept and the relationship is
  not a model feature, so every reported metric is unchanged.
- Gender is now derived from the first name. Previously it was drawn
  independently, so some notes used pronouns that did not match the resident's
  name. Gender is not a model feature and the random draw is retained, so all
  other values and every reported metric are unchanged.
